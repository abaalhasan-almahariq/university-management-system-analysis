# Stakeholders & User Stories

## Stakeholder Identification

The original project identifies the following stakeholder groups and responsibilities:

- **University students** — direct users of academic and administrative services.
- **Professors** — direct users responsible for teaching, exams, marks, and attendance.
- **Deanship of Student Affairs** — institutional stakeholder involved in student services.
- **Department of Information Technology** — identified as the requesting department in cooperation with university administration.
- **University Management / Financial Affairs** — identified as the funding stakeholder.
- **University counselor, academic committees, and vice president** — sources of academic policy.
- **Student Affairs and Maintenance departments** — identified as data owners in the original analysis.
- **Test engineer** — responsible for testing the system.
- **Maintenance engineer** — responsible for maintaining the system.
- **Internal development team with support from an external specialized company** — proposed development responsibility.

## User Story Format

The project uses the format:

> As a **[role]**, I want to **[feature]**, so that **[reason]**.

## Student User Stories

- As a **Student**, I want to create an account, so that I can be a PU member.
- As a **Student**, I want to log in to the system, so that I can ask for the services the university provides for students.
- As a **Student**, I want to register for a course, so that I can take it and learn from it.
- As a **Student**, I want to pay my university fees, so that I can continue my studies.
- As a **Student**, I want to see my marks, so that I can calculate my average.
- As a **Student**, I want to have access to online exams, so that I can solve them.

## Professor User Stories

- As a **Professor**, I want to create an account, so that I can be a PU crew member.
- As a **Professor**, I want to log in to the system, so that I can ask for the services the university provides for professors.
- As a **Professor**, I want to generate exams, so that I can test the students.
- As a **Professor**, I want to share students' marks, so that students can view them.
- As a **Professor**, I want to record students' attendance, so that I can record and use attendance information.

## Notes

These user stories are preserved from the original analysis and are intentionally presented as requirements/design artifacts rather than as claims about a completed implementation.
