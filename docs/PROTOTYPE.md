# Application Prototype

The original project includes a visual prototype covering both **student** and **professor** perspectives. The prototype is used to demonstrate how the requirements and UML models could translate into a usable interface.

## Student View

### Dashboard

The student dashboard provides a central overview of university information and quick access to major features such as courses, marks, attendance, payments, and related academic services.

### My Courses

The prototype includes a course view for the student's currently registered courses. It is intended to support quick access to course information and academic actions.

### Available Courses

A separate available-courses interface supports browsing and selecting courses for registration, corresponding to **UC-1 Register Course**.

### Attendance

The attendance view allows the student to review attendance information for registered courses.

### Submit Excuse

The prototype includes an absence-excuse workflow where a student can submit a reason for an absence and track the request, matching the `Excuse` class and attendance-related requirements in the analysis.

## Professor View

### Professor Dashboard

The professor prototype provides access to teaching-related workflows, including taught courses, student information, marks, attendance, exams, homework, and student requests.

## Design Role

The prototype is part of the software-analysis deliverable rather than a claim of a fully implemented production application. It serves as a visual validation of the requirements, use cases, and modeled workflows.
