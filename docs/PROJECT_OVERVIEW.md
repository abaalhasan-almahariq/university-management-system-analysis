# Project Overview

## Purpose

The University Management System (UMS) project proposes a web-based PU E-Learning / university management system for Palestine University. Its purpose is to digitize and streamline academic and administrative workflows that otherwise require significant paperwork and in-person processing.

The system is designed around two main direct user groups: **students** and **professors**, while also interacting with administrative units such as the Deanship of Admission and Registration, Student Affairs, faculty administration, and external banking/payment systems.

## Problem Domain

The original project identifies several university processes that are time-consuming when handled manually:

- course registration and withdrawal;
- fee payment;
- grade viewing;
- exam scheduling and online exams;
- homework submission;
- attendance tracking;
- absence excuse requests;
- professor management of courses, exams, marks, and attendance.

The proposed system centralizes these services so users can complete them electronically rather than through repeated paperwork and in-person visits.

## Proposed Solution

Students are expected to be able to:

- create and access university accounts using their IDs;
- register and remove courses;
- pay university fees using external payment methods such as Visa or eFAWATEERcom-style banking integration;
- view marks and calculate averages;
- submit homework;
- view attendance records;
- submit absence excuses;
- access exam schedules and online exams.

Professors are expected to be able to:

- log in using university credentials;
- view the courses they teach;
- see students registered in their courses;
- upload marks;
- record attendance;
- review attendance/absence-related requests;
- create exams and homework.

## Development Methodology

The project proposes using **Extreme Programming (XP)**, an Agile methodology centered around short iterative releases, customer involvement, user stories, incremental design, testing, and repeated feedback.

The documented lifecycle is:

1. **Planning and selecting user stories** — define goals, understand the problem domain, gather requirements, and break user stories into tasks.
2. **Design** — create a simple system design and divide implementation work across the team.
3. **Implementation** — develop the software incrementally while keeping the design as simple as possible.
4. **Testing** — perform unit testing and system testing to validate expected behavior.
5. **Deployment and evaluation** — present an iteration to the customer, gather feedback, and use it to guide the next version.

## Project Nature

This repository represents the **analysis, modeling, and prototype stage** of the system. It is not presented as a complete deployed production system.
