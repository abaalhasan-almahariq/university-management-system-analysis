# Requirements

## Functional Requirements

The project defines the following functional requirements:

- **FR1:** The system shall allow students and professors to create an account for PU E-Learning.
- **FR2:** The system shall allow students and professors to log in to PU E-Learning.
- **FR3:** The system shall allow students to register for courses through PU E-Learning.
- **FR4:** The system shall provide a payment gateway to let students pay fees through PU E-Learning.
- **FR5:** The system shall allow students and professors to view student marks.
- **FR6:** The system shall allow students and professors to calculate the average.
- **FR7:** The system shall allow professors to create online exams through PU E-Learning.
- **FR8:** The system shall allow professors to upload students' marks through PU E-Learning.
- **FR9:** The system shall allow professors to upload attendance through PU E-Learning.
- **FR10:** The system shall allow the faculty to assign courses.
- **FR11:** The system shall allow faculty to assign a lecturer.

## Non-Functional Requirements

The project defines the following non-functional requirements:

- **NFR1:** The system shall not exceed 3 seconds for the login process.
- **NFR2:** The system shall operate 24/7 with no more than 2 hours of downtime per month for maintenance.
- **NFR3:** The system shall support 10,000 concurrent users without downtime.
- **NFR4:** The system shall be compatible with major web browsers, including Chrome, Edge, and Safari.
- **NFR5:** The system shall display search results within 4 seconds.
- **NFR6:** The system shall automatically log the student out of the account when they finish working with the system.

## Scope Note

These requirements come from the original analysis document. They represent the intended behavior and quality goals of the proposed system, not measured production guarantees.
